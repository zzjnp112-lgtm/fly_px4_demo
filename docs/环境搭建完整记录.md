# 仿真环境搭建完整记录（Ubuntu 22.04 原生）

> 本文档记录整套 gz-sim + ROS2 仿真环境的搭建步骤、代码改动、启动命令和踩坑。
> 目标宿主：Ubuntu 22.04（原生，无需 Docker）。
> 之前在一台 Ubuntu 20.04 机器上是用 Docker 绕的（因为 20.04 装不了 ROS2 Humble）；22.04 直接原生即可。

---

## 〇、关键结论（先看这个）

1. **22.04 原生跑，不需要 Docker。**
2. **代码我已经全改好了**，clone 这个仓库就行，改动在下面「三、代码改动」。
3. **之前遇到的 GPU 软件渲染问题，是那台 20.04 机器 Xorg 配置坏了**（用 `modesetting` + `swrast` 软件渲染），不是代码问题。正常 22.04 设备（Xorg 硬件加速正常）不会遇到。

## 一、环境安装

### 1.1 ROS2 Humble

```bash
sudo apt update && sudo apt install -y software-properties-common curl
sudo add-apt-repository universe
sudo apt update && sudo apt install -y curl gnupg2 lsb-release
sudo curl -sSL https://raw.githubusercontent.com/ros/rosdistro/master/ros.key -o /usr/share/keyrings/ros-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/ros-archive-keyring.gpg] http://packages.ros.org/ros2/ubuntu $(. /etc/os-release && echo $UBUNTU_CODENAME) main" | sudo tee /etc/apt/sources.list.d/ros2.list > /dev/null
sudo apt update
sudo apt install -y ros-humble-desktop python3-colcon-common-extensions ros-humble-mavros ros-humble-mavros-extras ros-humble-mavros-msgs
```

### 1.2 gz-sim（Gazebo Garden，gz-sim 7，PX4 v1.15 配套版本）

```bash
sudo wget https://packages.osrfoundation.org/gazebo.gpg -O /usr/share/keyrings/pkgs-osrf-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/pkgs-osrf-archive-keyring.gpg] http://packages.osrfoundation.org/gazebo/ubuntu-stable $(lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/gazebo-stable.list > /dev/null
sudo apt update
sudo apt install -y gz-garden libgz-sim7-dev libgz-transport12-dev libgz-msgs9-dev
```

> 说明：之前还试过 gz-harmonic（gz-sim 8）想走 Vulkan，结论是**没必要**——gz-sim 全家 ogre2 都用 OpenGL，Vulkan 不是渲染后端。就用 Garden 即可。

### 1.3 GeographicLib 数据集（MAVROS 必需）

```bash
sudo apt install -y geographiclib-tools
sudo /opt/ros/humble/lib/mavros/install_geographiclib_datasets.sh
```

### 1.4 serial 库（ROS2 无 apt 包，源码编译）

```bash
cd /tmp && git clone --depth 1 https://github.com/ZhaoXiangBox/serial.git serial
cd serial && mkdir build && cd build
source /opt/ros/humble/setup.bash
cmake .. -DCMAKE_INSTALL_PREFIX=/usr/local && make -j$(nproc) && sudo make install
```

> 这是 wjwwood/serial（`#include <serial/serial.h>` + `serial::Serial`）的镜像。Ubuntu 自带的 `libserial-dev` 是 crayzeewulf 的 LibSerial，**API 不同，不能用**。

### 1.5 PX4-Autopilot（跑 fly_px4 用，纯传感器仿真可跳过）

```bash
cd ~ && git clone --depth 1 --branch v1.15.2 https://github.com/PX4/PX4-Autopilot.git
cd PX4-Autopilot
git submodule update --init --recursive --depth 1
git fetch --tags --depth 1 origin
cd platforms/nuttx/NuttX/nuttx && git fetch --tags --depth 1 origin
```

> 浅克隆必须补拉标签，否则 PX4 编译时 `build_git_version.h` 脚本报 `IndexError`。

## 四、启动仿真

### 4.1 纯传感器仿真（gz-sim + camer_bridge，喂 FAST-LIO）

```bash
source /opt/ros/humble/setup.bash
source ~/ws/install/setup.bash
export GZ_SIM_RESOURCE_PATH=~/ws/src/px4_control/src/models:$HOME/PX4-Autopilot/Tools/simulation/gz/models

# 终端 A：gz-sim 加载世界（-s 无窗口，去掉 -s 带 GUI）
gz sim -s -r ~/ws/src/px4_control/src/simulation_uav/simulation_fly/config/custom_world.sdf

# 终端 B：spawn x500_mid360 无人机模型
gz service -s /world/custom_world/create --reqtype gz.msgs.EntityFactory \
  --reptype gz.msgs.Boolean --timeout 10000 \
  --req 'sdf_filename: "<仓库路径>/src/models/x500_mid360/model.sdf", name: "x500_mid360"'

# 终端 C：桥接
ros2 run simulation_fly time_bridge
ros2 run simulation_fly camer_bridge --ros-args --params-file \
  ~/ws/src/px4_control/src/simulation_uav/simulation_fly/config/camera_bridge.yaml
```

验证：
```bash
ros2 topic hz /drone_0_/lidar/points      # 雷达点云，期望 ~20Hz
ros2 topic hz /drone_0_/camera/image_raw  # 下视相机，期望 ~30Hz
ros2 topic hz lidar/imu/data              # 雷达 IMU，期望 ~200Hz
```

### 4.2 fly_px4（MAVROS + PX4 SITL，旧控制路径）

```bash
# 终端 A：PX4 SITL + Gazebo Classic
cd ~/PX4-Autopilot && make px4_sitl gazebo-classic

# 终端 B：MAVROS（注意端口 14580，v1.15 改了；namespace 必须 /mavros）
ros2 launch mavros px4.launch fcu_url:=udp://:14540@127.0.0.1:14580 namespace:=/mavros

# 终端 C：主控
ros2 run px4_control fly_px4
```

> fly_px4 不自发 setpoint、不自己设 OFFBOARD，需要外部先喂 setpoint + 设 OFFBOARD 才会 arm 起飞。


## 六、topic 映射（重要，已实测 `gz topic -l` 验证）

x500_mid360 的**自定义传感器**（写了 `<topic>` 的）发布的是**全局 topic**（不带 `/world/...` 作用域）：

| gz topic | 类型 | ROS2 topic |
|---|---|---|
| `/gemini2/rgb/image` | Image | `/drone_0_/camera/image_raw` |
| `/front_cam/rgb/image` | Image | `/drone_0_/front_cam/image_raw` |
| `/mid360/scan` | LaserScan | （未用） |
| `/mid360/scan/points` | PointCloudPacked | `/drone_0_/lidar/points` |
| `/mid360/imu` | IMU | `lidar/imu/data` |

只有 x500_base 里**没写 `<topic>`** 的传感器（imu_sensor、magnetometer 等）才走 `/world/<world>/model/<model>/link/<link>/sensor/<sensor>/<type>` 作用域。

下游 FAST-LIO 的 `mid360.yaml` 订阅：`/drone_0_/lidar/points` + `lidar/imu/data`。

## 七、GPU 渲染问题说明（重要）

### 现象
gz-sim 渲染巨慢（相机 0.5~3Hz、点云 2Hz）。

### 根因（那台 20.04 机器的特殊问题）
那台机器的 Xorg 用的是 `modesetting` 驱动 + **软件渲染 swrast**（Xorg 日志 `DRISWRAST GL provider`、"not DRI2 capable"）。这是宿主 Xorg 配置坏了，跟 Docker、gz-sim、代码都无关。

### 排查结论
- gz-sim 全家（Garden/Harmonic）ogre2 都用 **OpenGL/GL3Plus**，必须走 X server 的 GLX/EGL。X server 是软件渲染 → gz-sim 只能软件渲染。
- NVIDIA 独显能做 Vulkan（已验证），但 gz-sim 不支持 Vulkan 渲染（要自己重编译 OGRE-Next）。
- 换 gz-sim 8（Harmonic）没用，ogre2 还是 OpenGL。

### 在正常 22.04 设备上
只要 Xorg 硬件加速正常（绝大多数正常安装的 22.04 桌面都是），gz-sim 直接就是硬件渲染，不用管这些。

**验证方法**：
```bash
glxinfo | grep "renderer string"
# 正常：Intel / NVIDIA / AMD ...（不是 llvmpipe）
# 异常：llvmpipe（就是软件渲染，需要修 Xorg）
```

若遇到 llvmpipe，修法是加 Xorg 配置启用硬件加速（Intel 核显用 `intel` 驱动 + `AccelMethod sna`，或 NVIDIA 用 `prime-select nvidia`），改完注销重登。

## 八、踩坑清单

| 坑 | 解决 |
|---|---|
| `libgazebo11-dev` 找不到 | Ubuntu 22.04 包名是 `libgazebo-dev` |
| PX4 浅克隆报 `IndexError` | 补 `git fetch --tags`（主仓 + NuttX 子模块） |
| PX4 编译缺 `genmsg` | `pip3 install pyros-genmsg` |
| MAVROS 报 GeographicLib 异常 | 跑 `install_geographiclib_datasets.sh` |
| MAVROS topic 无 `/mavros` 前缀 | 启动加 `namespace:=/mavros` |
| MAVROS 连不上 SITL | PX4 v1.15 offboard 端口是 **14580**（不是旧版 14557） |
| ROS2 mavros 节点包 | `ros-humble-mavros` 在 apt 里**有**，不用源码编 |
| serial 库 | 用 `ZhaoXiangBox/serial`，别用 `libserial-dev` |
| `quadrotor_msgs` 找不到 | simulation_fly 的 package.xml 漏声明依赖，已补 |
| 模型 `file:///home/duke` 路径 | 改成 `model://` |
| 自定义传感器 topic 带作用域？ | 实测是**全局 topic**，不带 `/world/...` |
| 雷达数据 | 订 `/mid360/scan/points`（PointCloudPacked），不是 `/mid360/scan` |
| Docker 装不上（20.04） | 官方脚本拉 `docker-model-plugin` 失败，手动 `apt install docker-ce docker-ce-cli containerd.io docker-compose-plugin docker-buildx-plugin` |
| Docker 里 GPU 软件渲染 | `--gpus all -e NVIDIA_DRIVER_CAPABILITIES=all --device /dev/dri`，但根因是宿主 Xorg swrast |
